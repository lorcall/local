# LoCal on the web

The same app as `apps-script/`, running from GitHub Pages instead of inside Apps Script.
Each person's meals live in a spreadsheet in **their own** Google Drive; this site stores
nothing and sees nothing beyond the files it creates for them.

## Why this exists

Apps Script serves its pages inside a Google frame, which costs two things that matter on a
phone: the page can't declare itself an installed web app (hence the white strip at the top
of the home-screen icon), and it can't open a live camera viewfinder. Both come back on an
origin of our own.

## How it fits together

| File | What it is |
| --- | --- |
| `index.html` | The shell: PWA metadata, safe-area handling, and the sign-in gate |
| `api.js` | `WebAPI()` — the server interface, re-implemented against Google's APIs |
| `app.js` | Generated by `build/build.js` from `build/src/*.js`. Do not edit |
| `styles.css` | Generated from `apps-script/styles.html`. Do not edit |
| `manifest.webmanifest` | Name, icons and `display: standalone` |

`build/src/2-api.js` picks its transport at load: `google.script.run` inside Apps Script,
`WebAPI()` when `api.js` has been loaded first, and the offline demo store otherwise. The
screens, charts and calculations are the same code in all three.

## Setup

1. **OAuth client ID.** Google Cloud Console → APIs & Services → Credentials → Create
   credentials → OAuth client ID → Web application. Add your Pages origin (for example
   `https://lorcall.github.io`, with no path) as an Authorized JavaScript origin. Enable the
   **Google Drive API** and the **Google Sheets API** for the project.
2. **Consent screen.** The only scope is `drive.file`, which is non-sensitive, so this takes
   the lighter verification path. Until the app is published you are limited to the test
   users you list.
3. **Deploy the proxy.** See `proxy/proxy.gs` — it holds the Gemini key and the allowlist.
4. **Fill in `CONFIG`** at the top of `api.js` with the client ID and the proxy's `/exec` URL.
5. **Turn on Pages.** Repo Settings → Pages → Deploy from a branch → `main` → `/` (root).
   The app is then at `https://<user>.github.io/<repo>/web/`.

## What is deliberately not here

No service worker yet. Offline support means queueing writes and reconciling them against a
Sheet that may have changed, which is worth doing properly rather than quickly.
